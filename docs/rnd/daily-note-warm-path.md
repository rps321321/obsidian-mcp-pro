# Daily Note Warm Path

_Status: active_
_Started: 2026-06-04 - Decided: _

## Hypothesis

`get_daily_note` is the daily-log entry point and is referenced by workflow
prompts. The current path reads `.obsidian/daily-notes.json`, formats the
configured date, reads the note, and renders frontmatter on every call. A
measured warm-path strategy may cut repeated configured daily-note reads by at
least 20% without changing date validation, configured folder/format handling,
frontmatter rendering, missing-note errors, or vault-boundary checks.

## Fixture

Bench command:

```powershell
npm run build
node scripts\bench-daily-notes.mjs 100,1000 --json
```

The harness creates temporary vaults with an Obsidian daily-note config at
`.obsidian/daily-notes.json`, two notes in `daily/`, and 100 or 1,000 synthetic
body lines per note. It calls `get_daily_note` for one date twice, then calls
`get_daily_note` for a second date through a real stdio MCP client.

Baseline captured on 2026-06-04 from the slower values across two sequential
runs:

| lines | cold get_daily_note | warm get_daily_note | warm get_daily_note other date |
|---:|---:|---:|---:|
| 100 | 8.7ms | 2.5ms | 2.5ms |
| 1,000 | 7.1ms | 1.9ms | 2.2ms |

## Metric

Primary metric: 1,000-line warm `get_daily_note` wall time.

Ship bar: warm `get_daily_note` at or below 1.5ms (20% faster than the 1.9ms
baseline), with 1,000-line cold `get_daily_note` no worse than 7.9ms and warm
other-date `get_daily_note` no worse than 2.5ms. Returned note path,
frontmatter header rendering, body content, missing-note errors, date parsing,
configured folder/format behavior, and vault-boundary checks must stay
unchanged.

| | before | after |
|---|---:|---:|
| 1,000-line warm get_daily_note | 1.9ms | |
| 1,000-line cold get_daily_note guardrail | 7.1ms | |
| 1,000-line warm get_daily_note other-date guardrail | 2.2ms | |

## Safety review

Data accessed: synthetic temporary markdown vaults generated by
`scripts/bench-daily-notes.mjs`. No real vault content, secrets, network calls,
or embedding providers are involved.

Writes performed: temporary fixture vault creation and deletion only.

Logs emitted: normal stdio server startup logs with temporary vault paths. No
note body content is logged.

Rollback path: drop any prototype and keep direct daily-note config reads plus
direct note reads.

## Kill criterion

Stop if the warm call improves by less than 20%, if cold or other-date
guardrails are exceeded, if daily-note config edits are not reflected on the
next call, or if the implementation needs a persistent index or filesystem
watcher to stay correct.
