# Broken Link Warm Path

_Status: active_
_Started: 2026-06-04 - Decided: _

## Hypothesis

`find_broken_links` already uses the shared content cache, but it still rebuilds
its alias map and reparses every wikilink on repeat calls. Reusing the same link
graph data path as `get_backlinks`, `get_outlinks`, and `get_graph_neighbors`
should cut the 1,000-note warm broken-link scan by at least 20% without changing
the grouped report text, folder scoping, alias resolution, or max-result cap.

## Fixture

Bench command:

```powershell
npm run build
node scripts\bench-broken-links.mjs 100,1000 --json
```

The harness reuses `scripts/bench-links.mjs` to create temporary vaults with 100
and 1,000 markdown notes. Every note has frontmatter aliases, links to the next
and previous note, a link through a nearby alias, and periodic broken links. It
then calls `find_broken_links` twice through a real stdio MCP client with
`maxResults: 100`.

Baseline captured on 2026-06-04:

| notes | cold broken links | warm broken links |
|---:|---:|---:|
| 100 | 28.4ms | 11.9ms |
| 1,000 | 264.3ms | 222.7ms |

## Metric

Primary metric: 1,000-note warm `find_broken_links` wall time.

Ship bar: warm time at or below 178ms (20% faster than the 222.7ms baseline),
with 1,000-note cold `find_broken_links` no worse than 291ms and no changed report text
for aliases, line numbers, folder-scoped clean reports, or max-result summaries.

| | before | after |
|---|---:|---:|
| 1,000-note warm broken-link scan | 222.7ms | |
| 1,000-note cold broken-link guardrail | 264.3ms | |

## Safety review

Data accessed: synthetic temporary markdown vaults generated by
`scripts/bench-links.mjs`. No real vault content, secrets, network calls, or
embedding providers are involved.

Writes performed: temporary fixture vault creation and deletion only. A future
prototype may route `find_broken_links` through the in-memory link graph cache;
it must preserve vault-boundary checks, symlink handling, folder scoping, alias
resolution, max-result truncation, and line-number lookup.

Logs emitted: normal stdio server startup logs with temporary vault paths. No note
body content is logged.

Rollback path: drop the prototype and keep the current direct scan.

## Kill criterion

Stop if the warm path improves by less than 20%, if cold broken-link scans exceed
the guardrail, if folder-scoped scans report cross-folder sources, or if the
implementation changes alias-resolved broken-link output.
