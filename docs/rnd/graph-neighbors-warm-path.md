# Graph Neighbors Warm Path

_Status: active_
_Started: 2026-06-04 - Decided: _

## Hypothesis

`get_graph_neighbors` is the link tool that turns the graph cache into a local
navigation map, but warm calls still pay cache validation plus source-path
resolution and traversal/rendering work. A small warm-path improvement should
cut the 1,000-note warm depth-2 traversal by at least 20% without changing
direction filtering, max-result truncation, alias-aware graph construction,
neighbor ordering, displayed paths, or stale-cache invalidation.

## Fixture

Bench command:

```powershell
npm run build
node scripts\bench-graph-neighbors.mjs 100,1000 --json
```

The harness creates temporary vaults with 100 or 1,000 markdown notes. Notes are
spread across `reference/` and nested `areas/team-*` folders, each note has a
unique frontmatter alias, and each links to the next note, a skip-ahead note, a
previous note by alias, a shared hub note by direct name, plus occasional broken
targets. It calls `get_graph_neighbors` cold on one source, then warm on a depth
2 `direction: "both"` source and a depth 3 `direction: "outbound"` source through
a real stdio MCP client.

Baseline captured on 2026-06-04 from the slower 1,000-note values across two
sequential runs:

| notes | cold graph neighbors | warm graph neighbors | warm outbound neighbors |
|---:|---:|---:|---:|
| 100 | 30.7ms | 9.1ms | 7.0ms |
| 1,000 | 76.4ms | 29.4ms | 26.9ms |

## Metric

Primary metric: 1,000-note warm `get_graph_neighbors` wall time for depth 2 and
`direction: "both"` after one graph-building call in the same server process.

Ship bar: warm depth-2 traversal at or below 23.5ms (20% faster than the 29.4ms
baseline), with 1,000-note cold traversal no worse than 84ms and warm outbound
depth-3 traversal no worse than 30ms. Direction filtering, traversal depth,
truncation behavior, output ordering, alias-derived edges, and escaping must stay
unchanged.

| | before | after |
|---|---:|---:|
| 1,000-note warm graph_neighbors | 29.4ms | |
| 1,000-note cold graph_neighbors guardrail | 76.4ms | |
| 1,000-note warm outbound graph_neighbors guardrail | 26.9ms | |

## Safety review

Data accessed: synthetic temporary markdown vaults generated by
`scripts/bench-graph-neighbors.mjs`. No real vault content, secrets, network
calls, or embedding providers are involved.

Writes performed: temporary fixture vault creation and deletion only. A future
prototype may cache or index graph traversal inputs, but it must preserve graph
cache mtime/file-set validation, path-boundary checks, symlink handling, depth
limits, max-result caps, and output shape.

Logs emitted: normal stdio server startup logs with temporary vault paths. No
note body content is logged.

Rollback path: drop the prototype and keep the current shared graph traversal
path.

## Kill criterion

Stop if the warm call improves by less than 20%, if cold or outbound guardrails
are exceeded, if traversal output changes, if stale graph data can survive after
a note edit, or if the implementation requires a persistent index or watcher to
stay correct.
