# Note Fragment Warm Path

_Status: active_
_Started: 2026-06-04 - Decided: _

## Hypothesis

`get_note` fragment reads are the safe way for agents to inspect long notes
without pulling the whole body into context. The current implementation still
reads the full file before slicing `lines`, `section`, or `block` fragments.
A measured fragment-specific path may cut warm line-range latency on long notes
by at least 20% without changing returned text, frontmatter handling for full
reads, vault-boundary checks, or fragment error messages.

## Fixture

Bench command:

```powershell
npm run build
node scripts\bench-note-fragments.mjs 1000,10000 --json
```

The harness creates temporary vaults with one markdown note containing 1,000 or
10,000 generated body lines, deterministic headings, frontmatter, a tag, and one
block id. It calls `get_note` with `lines: "40-60"` twice, then calls
`get_note` for `section: "Section 7"` and `block: "fragment-target"` through a
real stdio MCP client.

Baseline captured on 2026-06-04 from the slower values across two sequential
runs:

| lines | cold get_note lines | warm get_note lines | warm get_note section | warm get_note block |
|---:|---:|---:|---:|---:|
| 1,000 | 6.0ms | 1.9ms | 2.5ms | 2.2ms |
| 10,000 | 5.2ms | 2.4ms | 4.7ms | 5.5ms |

## Metric

Primary metric: 10,000-line warm `get_note` with a `lines` fragment.

Ship bar: warm `get_note` line fragments at or below 1.9ms (20% faster than the
2.4ms baseline), with 10,000-line cold line fragments no worse than 5.8ms, warm
section fragments no worse than 5.2ms, and warm block fragments no worse than
6.1ms. Returned fragment text, line numbering, heading/block matching,
frontmatter/tag output for full-note reads, vault-boundary checks, and escaped
displayed errors must stay unchanged.

| | before | after |
|---|---:|---:|
| 10,000-line warm get_note lines | 2.4ms | |
| 10,000-line cold get_note lines guardrail | 5.2ms | |
| 10,000-line warm get_note section guardrail | 4.7ms | |
| 10,000-line warm get_note block guardrail | 5.5ms | |

## Safety review

Data accessed: synthetic temporary markdown vaults generated by
`scripts/bench-note-fragments.mjs`. No real vault content, secrets, network
calls, or embedding providers are involved.

Writes performed: temporary fixture vault creation and deletion only.

Logs emitted: normal stdio server startup logs with temporary vault paths. No
note body content is logged.

Rollback path: drop any prototype and keep direct full-file reads for fragment
calls.

## Kill criterion

Stop if the warm line-fragment call improves by less than 20%, if cold,
section, or block guardrails are exceeded, if fragment output changes, or if the
implementation needs a persistent index or filesystem watcher to stay correct.
