# Bases Query Warm Path

_Status: shipped_
_Started: 2026-06-04 - Decided: 2026-06-04_

## Hypothesis

`query_base` already reads note bodies through the shared content cache, but it
still runs a second stat pass and reparses rows on repeat calls. Reusing cached
mtime data and/or parsed Base rows should cut the 1,000-note warm `query_base`
time by at least 20% without changing filters, view selection, stat-backed file
properties, link extraction, warnings, result order, or displayed output.

## Fixture

Bench command:

```powershell
npm run build
node scripts\bench-bases.mjs 100,1000 --json
```

The harness creates temporary vaults with 100 and 1,000 markdown notes plus one
`bases/projects.base` file. Notes include frontmatter `status`, `priority`, and
`owner` fields, inline tags, and one outgoing wikilink. The Base applies
base-level filters for `file.hasTag("bench")` and `status == "active"`, then a
view-level filter for `priority >= 3` and `file.name.contains("note")`. It calls
`query_base` twice through a real stdio MCP client.

Baseline captured on 2026-06-04:

| notes | cold query_base | warm query_base |
|---:|---:|---:|
| 100 | 28.8ms | 11.7ms |
| 1,000 | 149.0ms | 99.7ms |

## Metric

Primary metric: 1,000-note warm `query_base` wall time.

Ship bar: warm time at or below 80ms (20% faster than the 99.7ms baseline),
with 1,000-note cold `query_base` no worse than 164ms and no changed result text for
matching rows, warnings, or included frontmatter.

| | before | after |
|---|---:|---:|
| 1,000-note warm Base query | 99.7ms | 54.1ms / 57.0ms |
| 1,000-note cold Base query guardrail | 149.0ms | 84.8ms / 92.8ms |

## Safety review

Data accessed: synthetic temporary markdown and `.base` files generated by
`scripts/bench-bases.mjs`. No real vault content, secrets, network calls, or
embedding providers are involved.

Writes performed: temporary fixture vault creation and deletion only. A future
prototype may add in-memory Base row metadata; it must preserve vault-boundary
checks, symlink handling, stat-backed file properties, link extraction, and Base
parse warnings.

Logs emitted: normal stdio server startup logs with temporary vault paths. No note
body content is logged.

Rollback path: drop the prototype and keep the current direct query path.

## Kill criterion

Stop if the warm path improves by less than 20%, if cold Base queries exceed the
guardrail, if any supported filter returns different rows, or if stat-backed file
properties become stale.

## Decision

Ship. `readAllCached` now returns the stat fields it already gathers for each
safe, vault-boundary-checked markdown path, and `query_base` passes those fields
into `buildRow` instead of running a second stat pass. Repeated 1,000-note warm
queries landed at 54.1ms and 57.0ms against the 80ms ship bar, while cold runs
stayed at 84.8ms and 92.8ms against the 164ms guardrail. Result shape, filters,
warnings, link extraction, and stat-backed file properties remain unchanged.
