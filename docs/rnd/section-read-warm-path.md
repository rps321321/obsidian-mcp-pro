# Section Read Warm Path

_Status: active_
_Started: 2026-06-04 - Decided: _

## Hypothesis

`get_note` section reads are the targeted companion to `list_sections`: callers
discover headings, then fetch one section instead of the whole note. The current
path reads the full note and walks headings on each section call. A measured
section-read strategy may cut repeated late-section reads by at least 20%
without changing section matching, returned raw section text, missing-section
errors, line reads, block reads, full-note output, or vault-boundary checks.

## Fixture

Bench command:

```powershell
npm run build
node scripts\bench-section-reads.mjs 100,1000 --json
```

The harness creates temporary vaults with one markdown note containing 100 or
1,000 generated sections spread across levels 1-4. It calls `get_note` for a
late section twice, then calls `get_note` for an early section through a real
stdio MCP client.

Baseline captured on 2026-06-04 from the slower values across two sequential
runs:

| sections | cold late get_note section | warm late get_note section | warm early get_note section |
|---:|---:|---:|---:|
| 100 | 4.7ms | 1.3ms | 1.1ms |
| 1,000 | 5.6ms | 2.5ms | 2.0ms |

## Metric

Primary metric: 1,000-section warm `get_note` late-section wall time.

Ship bar: warm late-section reads at or below 2.0ms (20% faster than the 2.5ms
baseline), with 1,000-section cold late-section reads no worse than 6.2ms and
warm early-section reads no worse than 2.3ms. Returned section text, section
path matching, missing-section errors, line/block/full-note modes, and
vault-boundary checks must stay unchanged.

| | before | after |
|---|---:|---:|
| 1,000-section warm late get_note section | 2.5ms | |
| 1,000-section cold late get_note section guardrail | 5.6ms | |
| 1,000-section warm early get_note section guardrail | 2.0ms | |

## Safety review

Data accessed: synthetic temporary markdown vaults generated by
`scripts/bench-section-reads.mjs`. No real vault content, secrets, network
calls, or embedding providers are involved.

Writes performed: temporary fixture vault creation and deletion only.

Logs emitted: normal stdio server startup logs with temporary vault paths. No
note body content is logged.

Rollback path: drop any prototype and keep direct full-file reads followed by
`findSection`.

## Kill criterion

Stop if the warm late-section call improves by less than 20%, if cold or early
guardrails are exceeded, if any fragment mode changes output, or if the
implementation needs a persistent index or filesystem watcher to stay correct.
