# Canvas Read Warm Path

_Status: shipped_
_Started: 2026-06-04 - Decided: 2026-06-04_

## Hypothesis

`read_canvas` reparses the same `.canvas` JSON and rebuilds its display summary on
repeat calls. A tiny mtime-keyed canvas read cache may cut the 1,000-node warm
`read_canvas` time by at least 20% without changing path validation, malformed
JSON handling, node/edge ordering, control-character escaping, or displayed
output.

## Fixture

Bench command:

```powershell
npm run build
node scripts\bench-canvas.mjs 100,1000 --json
```

The harness creates temporary vaults with one `boards/map.canvas` file containing
100 or 1,000 nodes plus a chain of edges. Nodes mix text, file, and group types,
with coordinates, sizes, labels, colors, and previews. It calls `read_canvas`
twice through a real stdio MCP client.

Baseline captured on 2026-06-04:

| nodes | cold read_canvas | warm read_canvas |
|---:|---:|---:|
| 100 | 9.3ms | 3.8ms |
| 1,000 | 9.3ms | 6.9ms |

## Metric

Primary metric: 1,000-node warm `read_canvas` wall time.

Ship bar: warm time at or below 5.5ms (20% faster than the 6.9ms baseline),
with 1,000-node cold `read_canvas` no worse than 11ms and no changed output for
node previews, edge labels, counts, or escaped values.

| | before | after |
|---|---:|---:|
| 1,000-node warm read_canvas | 6.9ms | 1.7ms / 2.0ms |
| 1,000-node cold read_canvas guardrail | 11ms | 7.1ms / 8.0ms |

## Safety review

Data accessed: synthetic temporary `.canvas` files generated by
`scripts/bench-canvas.mjs`. No real vault content, secrets, network calls, or
embedding providers are involved.

Writes performed: temporary fixture vault creation and deletion only. The
prototype adds in-memory rendered canvas summaries; it preserves vault-boundary
checks, malformed JSON errors, mtime invalidation, and raw canvas file semantics.

Logs emitted: normal stdio server startup logs with temporary vault paths. Canvas
node content is returned to the client as the tool output being benchmarked, not
logged.

Rollback path: drop the prototype and keep direct `readCanvasFile` parsing per
call.

## Kill criterion

Stop if the warm path improves by less than 20%, if cold reads exceed the
guardrail, if malformed canvas behavior changes, or if displayed node/edge output
changes.

## Decision

Ship. `read_canvas` now keeps a small in-memory rendered-summary cache keyed by
the safe resolved file path, size, and mtime. Repeat reads still run the vault
path validation and stat check before serving cached output, while
`add_canvas_node` and `add_canvas_edge` clear their file's cached summary after
successful writes. Repeated 1,000-node warm reads landed at 1.7ms and 2.0ms
against the 5.5ms ship bar, and cold reads stayed at 7.1ms and 8.0ms against
the 11ms guardrail. Malformed JSON handling, node/edge ordering, control-character
escaping, and displayed output remain unchanged.
