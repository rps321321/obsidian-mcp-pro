# Orphan Discovery Warm Path

_Status: stopped_
_Started: 2026-06-04 - Decided: 2026-06-04_

## Hypothesis

`find_orphans` is a vault-hygiene tool that classifies notes with no backlinks,
no outlinks, or neither. It already uses the shared link graph path, but repeat
calls still spend measurable time validating and classifying the graph. A small
warm-path improvement should cut the 1,000-note warm call by at least 20%
without changing category counts, note ordering, `maxResults` truncation,
`includeOutlinksCheck`, alias-aware link resolution, or displayed paths.

## Fixture

Bench command:

```powershell
npm run build
node scripts\bench-orphans.mjs 100,1000 --json
```

The harness creates temporary vaults with 100 or 1,000 markdown notes. Notes are
spread across `archive/` and nested `areas/area-*` folders, with a mostly linked
graph plus deterministic fully-isolated notes, no-outlink notes, and no-backlink
notes. It calls `find_orphans` twice with `includeOutlinksCheck: true`, then once
with `includeOutlinksCheck: false` through a real stdio MCP client.

Baseline captured on 2026-06-04 from the slower 1,000-note values across two
sequential runs:

| notes | cold find_orphans | warm find_orphans | warm find_orphans backlink-only |
|---:|---:|---:|---:|
| 100 | 27.2ms | 6.8ms | 6.0ms |
| 1,000 | 420.6ms | 29.9ms | 31.7ms |

## Metric

Primary metric: 1,000-note warm `find_orphans` wall time with
`includeOutlinksCheck: true`.

Ship bar: warm `find_orphans` at or below 24ms (20% faster than the 29.9ms
baseline), with 1,000-note cold `find_orphans` no worse than 463ms and warm
`includeOutlinksCheck: false` no worse than 35ms. Category counts, listed paths,
category ordering, truncation, and line-safe path display must stay unchanged.

| | before | after |
|---|---:|---:|
| 1,000-note warm find_orphans | 29.9ms | 28.6ms / 27.9ms (not shipped) |
| 1,000-note cold find_orphans guardrail | 420.6ms | 440.1ms / 408.8ms (not shipped) |
| 1,000-note warm find_orphans backlink-only guardrail | 31.7ms | 25.8ms / 25.9ms (not shipped) |

## Safety review

Data accessed: synthetic temporary markdown vaults generated by
`scripts/bench-orphans.mjs`. No real vault content, secrets, network calls, or
embedding providers are involved.

Writes performed: temporary fixture vault creation and deletion only. A future
prototype may reuse derived orphan categories or reduce warm graph validation
work; it must preserve vault-boundary checks, mtime invalidation, alias-aware
link resolution, and raw note content behavior.

Logs emitted: normal stdio server startup logs with temporary vault paths. No
note body content is logged.

Rollback path: drop the prototype and keep direct classification from the link
graph on each call.

## Kill criterion

Stop if the warm call improves by less than 20%, if cold or backlink-only
guardrails are exceeded, if category counts or listed note paths change, if
stale orphan categories can survive after a note edit, or if the implementation
needs a persistent index or filesystem watcher to stay correct.

## Decision

Stop. Two low-risk prototypes missed the 24ms ship bar:

- Raising warm graph fingerprint stat concurrency from 16 to 64 produced
  repeated 1,000-note warm `find_orphans` calls of 29.2ms and 28.6ms.
- Raising it to 128 produced 29.7ms and 27.9ms.
- Precomputing derived orphan categories in the graph cache plus 64-way
  fingerprint stats produced 27.8ms and 30.7ms.

The results improved the backlink-only guardrail but did not reduce the primary
warm full orphan lookup by 20%, and precomputing categories adds state without
clearing the metric. No runtime change shipped. Future work should only reopen
this with a different freshness strategy, such as a carefully bounded watcher or
another way to avoid full warm stat validation without serving stale graph data.
