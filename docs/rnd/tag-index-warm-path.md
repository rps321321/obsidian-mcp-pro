# Tag Index Warm Path

_Status: active_
_Started: 2026-06-04 - Decided: _

## Hypothesis

`list_tags` and `search_by_tag` already read note bodies through the shared
content cache, but they still extract tags from every warm note on repeat calls.
A small tag-index cache keyed by vault path and note mtimes should cut the
1,000-note warm sparse `search_by_tag` time by at least 20% without changing tag
normalization, nested-tag matching, result order, previews, read-failure
handling, or displayed output.

## Fixture

Bench command:

```powershell
npm run build
node scripts\bench-tags.mjs 100,1000 --json
```

The harness creates temporary vaults with 100 and 1,000 markdown notes. Notes
include frontmatter tags, inline tags, nested topic/team/state tags, and a sparse
`special/target` tag that appears every 257 notes. It calls `list_tags` twice,
then calls `search_by_tag` for the sparse tag through a real stdio MCP client so
the search must inspect the whole vault instead of stopping early at `maxResults`.

Baseline captured on 2026-06-04:

| notes | cold list_tags | warm list_tags | warm search_by_tag |
|---:|---:|---:|---:|
| 100 | 16.9ms | 5.5ms | 6.3ms |
| 1,000 | 74.3ms | 35.7ms | 36.8ms |

## Metric

Primary metric: 1,000-note warm sparse `search_by_tag` wall time.

Ship bar: warm sparse `search_by_tag` at or below 29ms (20% faster than the
36.8ms baseline), with 1,000-note warm `list_tags` at or below 29ms and cold
`list_tags` no worse than 82ms. Matching rows, counts, previews, warnings, and
tag display must stay unchanged.

| | before | after |
|---|---:|---:|
| 1,000-note warm sparse search_by_tag | 36.8ms | |
| 1,000-note warm list_tags | 35.7ms | |
| 1,000-note cold list_tags guardrail | 74.3ms | |

## Safety review

Data accessed: synthetic temporary markdown files generated by
`scripts/bench-tags.mjs`. No real vault content, secrets, network calls, or
embedding providers are involved.

Writes performed: temporary fixture vault creation and deletion only. A future
prototype may add in-memory tag metadata; it must preserve vault-boundary checks,
mtime invalidation, read-failure behavior, frontmatter/inline tag parsing, and
the raw content cache contract.

Logs emitted: normal stdio server startup logs with temporary vault paths. No note
body content is logged.

Rollback path: drop the prototype and keep direct tag extraction per query.

## Kill criterion

Stop if the warm sparse search improves by less than 20%, if cold `list_tags`
exceeds the guardrail, if tag counts or nested-tag matches change, or if previews
use stale note content.
