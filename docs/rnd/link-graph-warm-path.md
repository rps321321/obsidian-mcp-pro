# Link Graph Warm Path

_Status: shipped_
_Started: 2026-06-04 - Decided: 2026-06-04_

## Hypothesis

`get_backlinks`, `get_outlinks`, `find_orphans`, and `get_graph_neighbors` share
one in-process link graph cache. A warm graph-backed call still lists every note
and stats each path to validate the cache. A smaller validation path should cut
the 1,000-note warm `get_backlinks` time by at least 20% without changing link
resolution, alias handling, traversal output, stale-cache invalidation, or vault
path checks.

## Fixture

Bench command:

```powershell
npm run build
node scripts\bench-links.mjs 100,1000 --json
```

The bench harness creates temporary vaults with 100 and 1,000 markdown notes.
Every note has frontmatter aliases, links to the next and previous note, a link
through a nearby alias, and periodic broken links. It then calls the public MCP
tools through a real stdio client:

- `get_graph_neighbors` on `note-000000.md` at depth 2 for the cold graph build.
- `get_backlinks` on `note-000001.md` for the primary warm-cache timing.
- `get_graph_neighbors` on `note-000010.md` for a second warm graph query.

Baseline captured on 2026-06-04:

| notes | cold graph neighbors | warm backlinks | warm graph neighbors |
|---:|---:|---:|---:|
| 100 | 33.1ms | 13.6ms | 9.8ms |
| 1,000 | 331.3ms | 80.4ms | 70.0ms |

## Metric

Primary metric: 1,000-note warm `get_backlinks` wall time after one graph-building
call in the same server process.

Ship bar: warm time at or below 64ms (20% faster than the 80.4ms baseline), with
1,000-note cold `get_graph_neighbors` no worse than 365ms and no changed result
text for alias-resolved backlinks or graph traversal.

| | before | after |
|---|---:|---:|
| 1,000-note warm backlinks | 80.4ms | 42.5ms |
| 1,000-note cold graph guardrail | 331.3ms | 280.7ms |

## Safety review

Data accessed: synthetic temporary markdown vaults generated by
`scripts/bench-links.mjs`. No real vault content, secrets, network calls, or
embedding providers are involved.

Writes performed: temporary fixture vault creation and deletion only. A future
prototype may adjust in-memory graph cache validation; it must preserve file-set
and mtime invalidation, the 30-second TTL, LRU bounds, symlink handling, and vault
path-boundary checks.

Logs emitted: normal stdio server startup logs with temporary vault paths. No note
body content is logged.

Rollback path: drop the prototype and leave the current cache behavior in place.

## Kill criterion

Stop if the warm path improves by less than 20%, if cold graph traversal exceeds
365ms on the 1,000-note fixture, if alias-resolved link output changes, or if the
implementation would weaken stale-cache detection or vault-boundary validation.

## Decision

Ship. The prototype keeps the existing graph cache, fingerprint, TTL, and result
shape, but passes one resolved vault root through each fingerprint validation
batch. `getNoteStats` still runs `resolveVaultPathSafe` for every note, so
per-note symlink and vault-boundary checks stay in place while avoiding a
repeated vault-root `realpath` syscall for each path.

Measured after the prototype with:

```powershell
npm run build
node scripts\bench-links.mjs 100,1000 --json
node scripts\bench-links.mjs 100,1000 --json
```

The two repeated 1,000-note warm backlink runs were 42.5ms and 37.0ms, both
below the 64ms ship bar. The slower repeated cold graph run was 283.7ms, below
the 365ms guardrail. A regression test keeps symlink escapes rejected when
`getNoteStats` receives a reused vault root.
