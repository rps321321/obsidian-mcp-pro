# Vault Stats Warm Path

_Status: active_
_Started: 2026-06-04 - Decided: _

## Hypothesis

`get_vault_stats` is a compact vault-health dashboard tool and a common
orientation call. It already reads note bodies through `readAllCached`, which
also returns per-note stat metadata, but the tool still runs a second mtime stat
pass. Reusing the cache-provided stats should cut the 1,000-note warm call by at
least 20% without changing note counts, byte/word totals, tag aggregation,
folder filtering, displayed paths, or most-recent-note selection.

## Fixture

Bench command:

```powershell
npm run build
node scripts\bench-vault-stats.mjs 100,1000 --json
```

The harness creates temporary vaults with 100 or 1,000 markdown notes. Notes are
spread across `journal/` and nested `projects/area-*` folders, include
frontmatter tags plus inline tags, and have deterministic hour-spaced mtimes. It
calls `get_vault_stats` twice for the whole vault, then once with
`folder: "projects"` through a real stdio MCP client.

Baseline captured on 2026-06-04 from the slower 1,000-note values across two
sequential runs:

| notes | cold get_vault_stats | warm get_vault_stats | warm get_vault_stats folder=projects |
|---:|---:|---:|---:|
| 100 | 25.4ms | 16.2ms | 5.8ms |
| 1,000 | 134.9ms | 94.6ms | 26.6ms |

## Metric

Primary metric: 1,000-note warm `get_vault_stats` wall time.

Ship bar: warm `get_vault_stats` at or below 76ms (20% faster than the
94.6ms baseline), with 1,000-note cold `get_vault_stats` no worse than 149ms and
warm folder-scoped `get_vault_stats` no worse than 30ms. Note counts, byte
totals, word totals, unique tag counts, untagged counts, folder labels, and
most-recent-note output must stay unchanged.

| | before | after |
|---|---:|---:|
| 1,000-note warm get_vault_stats | 94.6ms | |
| 1,000-note cold get_vault_stats guardrail | 134.9ms | |
| 1,000-note warm get_vault_stats folder=projects guardrail | 26.6ms | |

## Safety review

Data accessed: synthetic temporary markdown vaults generated by
`scripts/bench-vault-stats.mjs`. No real vault content, secrets, network calls,
or embedding providers are involved.

Writes performed: temporary fixture vault creation and deletion only. A future
prototype may reuse stat metadata already gathered by the safe content cache; it
must preserve vault-boundary checks, cache invalidation, mtime freshness, and
folder filtering.

Logs emitted: normal stdio server startup logs with temporary vault paths. No
note body content is logged.

Rollback path: drop the prototype and keep the direct second stat pass.

## Kill criterion

Stop if the warm call improves by less than 20%, if cold or folder guardrails
are exceeded, if stats differ for changed notes, or if the implementation needs
a persistent index or filesystem watcher to stay correct.
