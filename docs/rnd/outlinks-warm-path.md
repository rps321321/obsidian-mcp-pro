# Outlinks Warm Path

_Status: shipped_
_Started: 2026-06-04 - Decided: 2026-06-04_

## Hypothesis

`get_outlinks` is the fast way to audit a single note's downstream references,
but it still pays the shared link graph warm-validation cost on repeated calls.
A small warm-path improvement should cut the 1,000-note warm call by at least
20% without changing valid/broken/embed grouping, alias-aware resolution,
source path matching, displayed paths, or line-safe output.

## Fixture

Bench command:

```powershell
npm run build
node scripts\bench-outlinks.mjs 100,1000 --json
```

The harness creates temporary vaults with 100 or 1,000 markdown notes. Notes are
spread across `reference/` and nested `projects/team-*` folders, include
frontmatter aliases, and link to previous/next notes, alias targets, embeds, and
occasional broken targets. It calls `get_outlinks` cold on the first note, then
warm on a normal source and warm on a mixed valid/broken/embed source through a
real stdio MCP client.

Baseline captured on 2026-06-04 from the slower 1,000-note values across two
sequential runs:

| notes | cold get_outlinks | warm get_outlinks | warm get_outlinks mixed |
|---:|---:|---:|---:|
| 100 | 35.8ms | 8.0ms | 9.4ms |
| 1,000 | 638.5ms | 40.2ms | 34.1ms |

## Metric

Primary metric: 1,000-note warm `get_outlinks` wall time.

Ship bar: warm `get_outlinks` at or below 32ms (20% faster than the 40.2ms
baseline), with 1,000-note cold `get_outlinks` no worse than 703ms and warm
mixed-output `get_outlinks` no worse than 38ms. Valid, broken, and embed rows,
resolved paths, alias resolution, source matching, and escaping must stay
unchanged.

| | before | after |
|---|---:|---:|
| 1,000-note warm get_outlinks | 40.2ms | 29.6ms |
| 1,000-note cold get_outlinks guardrail | 638.5ms | 74.8ms |
| 1,000-note warm get_outlinks mixed guardrail | 34.1ms | 27.6ms |

## Safety review

Data accessed: synthetic temporary markdown vaults generated by
`scripts/bench-outlinks.mjs`. No real vault content, secrets, network calls, or
embedding providers are involved.

Writes performed: temporary fixture vault creation and deletion only. The shipped
prototype keeps the cache in process memory and still validates the graph from the
vault file set and note mtimes before returning warm results. It adds no
persistent index or watcher.

Logs emitted: normal stdio server startup logs with temporary vault paths. No
note body content is logged.

Rollback path: drop the prototype and keep direct rendering from the shared link
graph on each call.

## Kill criterion

Stop if the warm call improves by less than 20%, if cold or mixed-output
guardrails are exceeded, if valid/broken/embed grouping changes, if stale
outlinks can survive after a note edit, or if the implementation needs a
persistent index or filesystem watcher to stay correct.

## Decision

Shipped. The graph now builds a note-path index once per graph refresh and stores
resolved outlink rows during the build pass. That removes repeated all-note scans
for basename/alias-heavy vaults and lets `get_outlinks` render from already
resolved graph data. The slower repeated 1,000-note warm run landed at 29.6ms,
below the 32ms ship bar, while cold and mixed-output calls stayed under their
guardrails.
